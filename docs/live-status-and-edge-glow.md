# 实时动作与屏幕边缘光效

versionCode 59 保留恢复的 `ControlEdgeGlow`，接入新版悬浮窗的任务、
暂停、确认、接管、截图隐藏和触摸穿透生命周期。所有描边宽度乘以 2；渐变旋转
周期由 9 秒改为 0.9 秒，绘制跟随屏幕刷新。光效窗口不接收触摸或焦点。
Android 13+ 通过 AGSL 连续计算光晕衰减并做空间抖动，替代原有五层固定透明度描边；
较旧 Android 使用 64 层细分回退。旧的上游 `EdgeBeam` 源码和测试保留，但控制
悬浮窗使用 `ControlEdgeGlow`。

## 普通 Codex 工作

监控同时支持 `rollout-时间-线程UUID.jsonl` 与
`rollout-时间-线程UUID_存储UUID.jsonl`，使用前一个 UUID 作为规范线程 ID。
旧实现将后一种文件名整个过滤，导致实际正在执行的普通任务无法提升通知。

除了旧的 `event_msg`，现在也读取当前后端写入的 `response_item` 工具调用及
`item_completed` 记录，只提取事件类型、工具名称和生命周期标识，不展示参数、
命令输出或推理正文。思考、执行命令、修改文件和整理结果均可用于工作胶囊，
仍需观察到真实的任务开始，并在匹配的任务结束后收回。

## 跟随屏幕刷新率

Android 桌面窗口在前台时优先选择当前物理分辨率下最快的显示模式，退出前台后
释放偏好；显示视图同时请求系统的高刷调度类别。X11 的 Surface 清除固定帧率
投票，避免把进入窗口时的 60 Hz 再投给系统而锁住刷新率；
现有原生窗口变更协议以整数 Hz 同步 X11，分数刷新率取最近整数。
`DisplayListener` 在刷新率变化时同步，不再要求窗口同时改变尺寸。

取值优先使用 `Display.getMode()`，避免把应用兼容性覆盖的 60 Hz 当成物理屏幕
刷新率。光效跟随 `Choreographer` / `postInvalidateOnAnimation`，旧光束的固定
帧间隔节流已移除。退出可见状态后释放高刷请求。系统用户设置、温控和负载仍会
影响实际分配的模式及实际帧率；本次没有修改手机全局刷新率设置。

## 灵动岛内容

手机通知使用与悬浮窗相同的 `StatusLines` 本地化前缀解析，去掉“免确认”和
“Codex 正在操作”的固定前缀，直接展示具体操作。短状态示例：

| 动作 | 收起状态 | 展开内容 |
| --- | --- | --- |
| 读取屏幕 | 看屏幕 | Codex 正在看屏幕、当前应用、最近操作 |
| 点「发送」 | 点发送 | 点「发送」、当前应用、最近操作 |
| 输入内容 | 正在输入 | 与悬浮窗一致的输入状态、当前应用、最近操作 |
| 确认请求 | 等待确认 | 当前动作和所在应用，确认仍在原确认界面完成 |
| 暂停 | 已暂停 | 当前动作，提供继续和停止按钮 |

五字逐字符滑动已改为完整短语。长按钮名称在动作和带省略号的目标摘要之间轮换，
避免每次更新都只显示固定前缀。完整内容通过标准 `BigTextStyle` 展开。
通知保留最多三条最近操作；它们在状态入口记录，不依赖每次状态都实际发出通知。
历史随任务 ID 切换清空。暂停、继续和停止均绑定通知创建时的任务。

## 跨进程优先级

手机操控在应用主进程，Linux 运行服务在 `:runtime` 进程。手机任务存在时，
仅手机通知申请实时活动提升；普通 Codex 工作通知保留但不申请提升。手机通知
发布或取消后发送包内通知，由非导出的接收器立即刷新运行通知。运行服务读取
系统保存的本应用活动通知，而非使用跨进程不共享的静态变量。

手机通知有 15 秒超时并定期续期；主进程异常退出后，工作通知的定时刷新会在
其超时后恢复。手机任务正常结束则立即取消并恢复普通工作状态。

## ColorOS 展示边界与验证

本次使用 Android 标准 Live Updates；所有状态均使用启动器的同一透明图案，
移除旧双竖条及系统动作图标切换。通知图标遵循系统的单色显示与背景规则；
胶囊宽度、左右区域和卡片排版仍由系统控制。
OPPO 文档 12658 描述的是泛在服务 OML 模板，其 `leading` / `trailing` 并非
本应用可直接设置的 `Notification` 字段。源码没有模拟未公开的厂商接口，亦未
宣称已完成 OML 服务注册或审核。

本机验证包括 Android 主代码/手机测试代码编译、1,428 项手机 JVM 回归、
84 项生命周期、普通工作识别、短状态和刷新率策略 JVM 回归，以及 13 项输入法
桥接回归和离线 Chromium 焦点测试。用户启动的实际
任务经去除内容后的事件回放，验证可识别开始、命令执行和完成；手机上的离屏
GPU 测试验证着色器可编译、可绘制，并得到 59 个不同透明度样本、中心透明。
这些检查不等于新版胶囊与高刷窗口的实机验收，实际卡片、动画和显示切换仍需
安装新版后验证。
